# Tools → Edit Annotation：内存批量修改手动验收

更新日期：2026年10月24日。

当前采用 FreeText Replace All 的处理流程：修改当前打开的内存 Document，保留全部 session，标记未保存，由用户手动保存。
之前的“关闭 session、修改临时 PDF、校验、替换原文件、重新打开”流程已停用。

本次只做静态检查，未运行 APP、未构建，未操作实际 PDF、设置或索引数据库。
请使用测试文件验收，并区分 Apply 的内存修改与后续手动保存。

## 窗口和独立属性选项

- Tools → Edit Annotation… 打开居中模态窗口，显示目标文件名及完整路径，按钮为 Apply。
- 当前仅支持 Highlight；Color 默认“不修改”，Opacity 默认不勾选，此时 Apply 不可用。
- 仅修改颜色、仅修改 Opacity、同时修改两者均可；自定义颜色取消后保留原选择。
- Opacity 范围 5%–100%，100% 为完全不透明。
- 选择“不修改”的属性保留每个 Highlight 自己的原值，包括低于 5% 的原不透明度。
- Scope 默认打开对话框时的当前页，可切换整个 Document。
- 无 PDF、索引执行或重名预检查期间不能开始；操作进行时不能重复 Apply 或关闭对话框。

## 内存修改与确认

- 先在 PDF 中添加一些尚未保存的 FreeText、Square 或其他编辑，再执行 Highlight 批量修改。
- 不应出现先保存/放弃已有编辑的提示；原有未保存编辑继续保留。
- 检查后显示范围、匹配数量、实际修改数量和要改的属性，确认默认选择“否”。
- 确认文字明确：本次操作不支持 Undo，会清除该文档旧撤销记录，但不自动保存；放弃修改将丢弃整个文档所有未保存编辑。
- 取消确认、没有 Highlight 或属性已经全部符合要求，不新增批量修改，也不清除原有撤销记录或未保存状态。
- 成功修改后标记文档未保存、清除旧撤销记录，提示已修改数量及“请手动保存”。
- 文件名、磁盘 PDF 内容、Document 实例、session 数量和顺序保持不变，不产生临时 PDF 或备份。
- 操作本身不自动保存、不调用 Save Incremental、不关闭或重新打开 PDF。

## 显示刷新与共享 session

- 单页和 Continuous 两种模式都能修改，颜色和不透明度即时刷新。
- 文档范围修改后，滚动到此前显示过的离屏页面，不应显示旧 Highlight 属性。
- 同一 PDF 在左右两侧及多个标签中打开，全部 session 保留；活动视图同步刷新，非活动标签再次打开时读取新属性。
- 保留页码、缩放、阅读位置和全局注释添加模式，垂直同步不应产生意外跳动。
- 修改 Highlight 不改变文字、位置、QuadPoints 或混合模式；检查老 Foxit 高亮仍不遮住文字。
- 其他 PDF 的内容和未保存状态不受影响；Highlight 操作不应清掉此前的 FreeText 内容修改。
- 对话框显示检查/修改进度和结果，处理期间保持打开；完成后由用户点击 Close 关闭。

## 失败处理与保存回归

- 预检查或用户确认前失败，不应产生 Highlight 修改，错误详细信息和 Debug Log 可查看调用栈。
- 若修改中途失败，提示已完成数量及可能存在部分内存修改，保守标记未保存并清除旧撤销记录，不假装整批回滚。
- 部分修改也应尝试刷新全部活动视图；磁盘 PDF 仍未写入，不出现临时文件清理或文件替换错误。
- 关闭文档并选择放弃，可以回到磁盘版本，但同一文档其他未保存编辑也会丢弃。
- 手动 Save Incremental 后，仍严格执行增量保存、关闭旧 Document、从磁盘重新打开、刷新共享视图的原有流程。
- 保存后再次编辑和保存，检查 Foxit/QPDF 兼容性；本次不改变原有保存、备份和 QPDF 检查设置。
- 索引不自动更新；保存到磁盘后，如需更新索引，应手动执行 Index Management 的 Update。
